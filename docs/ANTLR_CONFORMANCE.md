# ANTLR 4.13.2 完整兼容目标

交付目标是让通过 ANTLR 4.13.2 校验的组合语法、独立 Lexer 和 Parser 语法能够用 MoonBit 目标生成并运行。语法结构、规则属性、动作位置及谓词求值时机保留其 ANTLR 语义。嵌入的 Java、C# 等宿主语言正文需要迁移为 MoonBit，绑定位置和可见值由生成器保留。对无宿主代码的语法，目标是保留原 `.g4` 内容直接生成。

运行时以 ANTLR 4.13.2 Java 目标为参照。在相同输入和等义宿主代码下，对照 Token 序列、所选分支、规则和错误节点、回调顺序、诊断位置与恢复后可用的节点。严格的全量解析入口保留给配置校验。另提供符合 ANTLR 规则调用语义的前缀解析入口，显式 `EOF` 的语法仍要求消耗到末尾。

| 兼容项 | 处理方案与通过标准 | 现状 |
| --- | --- | --- |
| 语法文件、导入与生成 | 复用原版 Tool 的语法分析、语法导入和 Token 词表。覆盖组合／拆分语法、`import`、`tokenVocab`、Token／通道声明、选项、标签和 `caseInsensitive`。对每类语法执行同源生成、编译、解析和对照 | 组合／拆分、词表、标签已验证。其余用上游用例补齐覆盖 |
| 规则参数、返回值与局部属性 | 从规则 AST 和调用点生成类型化参数、返回结构与逐次调用的属性帧。保留命名属性和标签引用，参数表达式使用 MoonBit 实现。验证递归调用的属性相互隔离 | 待实现属性帧及表达式绑定 |
| 动作和语义谓词 | 生成 Lexer 与 Parser 动作绑定，绑定显式携带规则、动作或谓词编号。词法动作只在匹配胜出后提交，语法动作只在选定路径执行。谓词支持前瞻与上下文属性，预测期分支只检查谓词，副作用不得执行。对照失败分支、动作时机、局部属性及重复解析 | Parser 与 Lexer 的无状态谓词回调已验证。上下文谓词和用户动作待实现 |
| Parser 预测 | 用带返回栈和语义条件的 ATN 配置集合执行 SLL。识别冲突后以实际调用栈执行 LL 重算，区分唯一解、歧义和无可行分支，按上游分支顺序解析歧义。对照嵌套空规则、共享长前缀、调用上下文冲突及带谓词的冲突 | 已有 SLL、全上下文回退和 DFA。本轮移除固定 64 Token 的前瞻截断，长前缀用例检查实际预测长度。上游冲突分类与选择规则待补齐 |
| Lexer | 对照最长匹配、同长规则顺序、fragment、模式和通道、非贪婪路径、谓词及 EOF 匹配。对照 Token 类型、文本、位置、通道和动作顺序 | 已覆盖模式、通道、非贪婪及纯谓词。EOF 边界和自定义词法动作待完善 |
| 错误处理及树 API | 对照默认 Lexer 恢复和 Parser 的单 Token 插入／删除、上下文同步和连续诊断。保留错误节点、合成 Token 区间及后续节点。分别验收规则前缀、显式 EOF、Listener 顺序和 Visitor 返回值 | 已有严格解析、显式同步恢复及规则前缀入口。14 个前缀用例对照所选树、首个剩余 Token 及显式 EOF。默认恢复策略、错误节点、惰性词法处理及其余预测场景待补齐 |

## 通过标准

1. 用固定版本的 ANTLR Tool 和 Java runtime 生成参考结果。移植 ANTLR 4.13.2 的 Lexer、Parser、语义谓词、动作与错误处理测试，按功能分类纳入 CI。
2. 无宿主代码的用例直接复用原语法。含宿主代码的用例使用等义的 MoonBit 绑定，分别检查动作顺序、属性值和输出。每个兼容项至少覆盖成功、失败与边界输入。
3. 对照只归一化目标语言的类型名称、宿主代码拼写和允许的诊断措辞。语法接受结果、选定分支、Token、树、回调次序、诊断位置和恢复后的结构应一致。用例未迁移、失败或存在未解释差异时，相关能力仍标记为未达标。
4. 完整兼容验收要求上述各类用例在 wasm、wasm-gc、JS、native 全部通过，并能复现生成结果。当前进度以 [兼容矩阵](ANTLR_COMPATIBILITY.md) 和 [对照测试清单](../tests/oracle-manifest.json) 为准。
