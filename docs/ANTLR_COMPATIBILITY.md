# ANTLR4 兼容矩阵

对照版本为 ANTLR 4.13.2。当前状态以仓库的运行时和测试为准。计划交付列列出本轮拟实现的范围。

| 能力 | 当前状态 | 计划交付与验收 |
| --- | --- | --- |
| `.g4` 与生成工具 | 已验证组合语法、独立 Lexer/Parser、`tokenVocab` 和标准 `-Dlanguage=MoonBit` 入口 | 保留标准命令入口，用新增语法验证生成物可编译并执行 |
| Lexer 与 Token 流 | 已验证最长匹配、规则顺序、fragment、模式、通道和内建动作 | 继续对照 Java 的 Token 类型、文本、位置和通道 |
| Parser 与预测 | 已验证直接左递归、优先级及左右结合性。SLL、全上下文回退及 DFA 缓存已有实现，歧义处理仍有差异 | 保留共同前缀、上下文消歧和优先级的对照用例，记录已知差异 |
| 上下文与遍历 | 已验证规则上下文、元素和列表标签、分支标签及 Visitor／Listener | 对新支持的语法继续验证树形和回调顺序 |
| 语义谓词 | 遇到谓词会显式报错 | 为 Parser 左边缘的无副作用谓词生成绑定入口，按规则和谓词编号调用 MoonBit 布尔回调，提供当前前瞻 Token 和调用信息。谓词返回 false 时剔除候选分支。用相同输入在真、假两种配置下与 Java 对比分支选择，再验证同一语法反复解析时缓存不会复用上次的谓词结果 |
| 非贪婪词法决策 | 遇到非贪婪决策会显式报错 | 支持 Lexer 的 `*?`、`+?`，区分规则内部的路径选择和规则之间的最长匹配。对照连续块注释、注释后的普通 Token、未闭合输入，以及竞争规则的 Token 边界 |
| 诊断与错误恢复 | 可报告带行列的词法和语法错误，解析入口遇错即失败 | 提供单独的恢复入口，返回诊断与部分解析树。首版覆盖单 Token 插入、删除及按显式同步点继续解析。用缺分隔符、多余 Token 和连续语句输入验证诊断位置、修复位置及后续节点，检查 EOF 和恢复预算能终止处理 |
| 目标语言代码与属性 | 内嵌动作、自定义词法动作和规则参数／返回属性超出当前支持范围 | 首版谓词需由使用者绑定 MoonBit 回调。任意 Java 等目标语言代码的自动翻译、Lexer 谓词和依赖局部属性的谓词不纳入本轮交付 |

语义谓词与非贪婪 Lexer 用例将接入官方 Java 对照生成流程。恢复用例对照诊断位置与后续可用节点，完整 Java 恢复策略和逐字诊断一致性留待扩展。当前验证范围和复现命令见 [验证说明](VERIFICATION.md)。
