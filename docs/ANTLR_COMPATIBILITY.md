# ANTLR4 兼容矩阵

对照版本为 ANTLR 4.13.2。当前状态以仓库的运行时和测试为准。验收列记录已验证行为及限制。完整兼容目标、处理方案和通过标准见 [ANTLR 4.13.2 兼容目标](ANTLR_CONFORMANCE.md)。

| 能力 | 当前状态 | 验收依据与边界 |
| --- | --- | --- |
| `.g4` 与生成工具 | 已验证组合语法、独立 Lexer/Parser、`tokenVocab` 和标准 `-Dlanguage=MoonBit` 入口 | 保留标准命令入口，用新增语法验证生成物可编译并执行 |
| Lexer 与 Token 流 | 已验证最长匹配、规则顺序、fragment、模式、通道和内建动作 | 继续对照 Java 的 Token 类型、文本、位置和通道 |
| Parser 与预测 | 已验证直接左递归、优先级及左右结合性。SLL、全上下文回退及 DFA 缓存已有实现，新增外部返回路径和冲突终止分类。已移除 64 Token 的固定前瞻截断 | 保留共同前缀、上下文消歧和优先级的对照用例，记录已知差异 |
| 上下文与遍历 | 已验证规则上下文、元素和列表标签、分支标签及 Visitor／Listener | 对新支持的语法继续验证树形和回调顺序 |
| 语义谓词 | 支持由 MoonBit 回调绑定的无副作用 Parser 与 Lexer 谓词 | 已为含谓词的 Parser 生成绑定入口，按规则和谓词编号调用 MoonBit 布尔回调，提供当前前瞻 Token 和调用信息。谓词返回 false 时剔除候选分支。用相同输入在真、假两种配置下与 Java 对比分支选择，再验证同一语法反复解析时缓存不会复用上次的谓词结果 |
| 非贪婪词法决策 | 支持 Lexer 的 `*?` 与 `+?` | 支持 Lexer 的 `*?`、`+?`，区分规则内部的路径选择和规则之间的最长匹配。对照连续块注释、注释后的普通 Token、未闭合输入，以及竞争规则的 Token 边界 |
| 诊断与错误恢复 | 严格入口报告行列。有界编辑恢复与默认局部恢复分别提供 | 已提供单独的恢复入口，返回诊断与部分解析树。首版覆盖单 Token 插入、删除及按显式同步点继续解析。用缺分隔符、多余 Token 和连续语句输入验证诊断位置、修复位置及后续节点，检查 EOF 和恢复预算能终止处理。`parse_default` 另按调用上下文恢复，434 项 Java 对照检查完整错误树、错误 Token 元数据、动作偏移和诊断位置 |
| 目标语言代码与属性 | Lexer 用户动作可绑定并修改 Token。Parser 用户动作可在接受后按路径回放，语义入口可绑定规则参数、返回值、局部值及后续谓词，已生成基本类型属性记录，新增实际路径执行、属性和可见谓词预测；完整上游语义用例仍待覆盖 | 首版谓词需由使用者绑定 MoonBit 回调。目标语言代码需手工迁移。属性、动作与规则调用的兼容实现见完整兼容目标 |

语义谓词与非贪婪 Lexer 用例已接入官方 Java 对照生成流程。恢复用例对照诊断位置与后续可用节点，默认恢复入口已对照局部插入／删除、上下文同步和连续错误；更广的上游分类用例仍未全部迁移，诊断措辞不要求逐字一致。当前验证范围和复现命令见 [验证说明](VERIFICATION.md)。
