## Local commands

```sh
moon fmt --check
moon check --deny-warn
moon build --deny-warn
moon test --deny-warn
moon test --target wasm-gc --deny-warn
moon test --target js --deny-warn
moon test --target native --deny-warn
moon run examples/typed
moon run cmd/main
```

The baseline uses moonc 0.10.20. All declared runtime logic is MoonBit and has
no external package dependency beyond the standard library.

## Independent Java reference

`tools/Oracle.java` loads parsers and lexers generated by the unmodified ANTLR
4.13.2 Java target. `tools/oracle.py` generates deterministic cases:

| Grammar | Cases | Accepted by the reference |
| --- | ---: | ---: |
| Imports, case-insensitive Lexer, custom channels and token types | 8 | 4 |
| JSON | 98 | 81 |
| Arithmetic | 65 | 55 |
| Split lexer/parser with modes | 15 | 12 |
| CSV | 34 | 30 |
| Precedence / associativity | 75 | 64 |
| Prefix, postfix, ternary and nested EBNF | 80 | 29 |
| Typed labelled grammar | 44 | 38 |
| Context-sensitive / ambiguous decisions | 26 | 22 |
| Predicate gating | 4 | 4 |
| Lexer predicate gating | 4 | 4 |
| Rule prefix entry points | 14 | 9 |
| Demand-driven rule prefix entry points | 17 | 12 |
| Default recovery and committed actions | 434 | Compared even when recovered |
| Lexer actions, recovery, and explicit EOF | 12 | 4 |
| Parser actions and left recursion | 4 | 4 |
| Stateful custom Lexer actions | 7 | 7 |
| Rule arguments, returns and local values | 3 | 3 |
| Non-greedy lexer decisions | 6 | 4 |

Accepted cases compare the complete rule-labelled tree and every emitted token's
type, text, scalar offsets, line, column and channel. For strict entry tests,
rejected cases must also be rejected by MoonANTLR. Lexer recovery cases
compare recovered Token sequences, lexical diagnostic positions, and action
offsets even for inputs with lexical errors. Seeds and counts are recorded in
`tests/oracle-manifest.json`; the expected outputs are committed so running
the tests does not require Java.

There are 963 core oracle comparisons, plus 39 original C# input cases,
19 C# recovery comparisons and 39 internal helper snapshots
in `csharp/oracle-manifest.json`. Stateful Lexer cases compare custom
mode changes, MORE, EOF remapping, supplementary Unicode, and final EOF metadata.
Attribute cases compare Java results and trees after call-site argument
binding, per-invocation local updates, and contextual predicates.
Parser action cases compare the
selected rule tree and action offset sequence, including left recursion.
Prefix entry cases compare the rule
tree and the first unconsumed visible Token, and cover explicit EOF and a
missing operand after a committed repetition. Accepted cases verify exact trees,
not merely acceptance. Decision cases include caller-sensitive short/long
alternatives, ambiguity order and common prefixes longer than the predictor's
former 64-token window. Left-recursion cases exercise nested EBNF stars to prevent
accidental creation of recursive contexts at unrelated loop entries.

Default recovery comparisons check the complete error-node tree, ordered
lexical and syntax diagnostic positions, all error Token metadata (including
synthetic intervals), remaining Token, and committed action offsets.

C# comparisons regenerate with `python tools/csharp_oracle.py --jar /path/to/antlr-4.13.2-complete.jar`.

Generated API tests check optional/list labels, left/right operand identity,
alternative narrowing, spans, Visitor results and Listener event order.
Prediction tests require full-context fallbacks and DFA cache hits.
`python tools/check_target.py --jar /path/to/antlr-4.13.2-complete.jar` separately
builds the plugin and checks the real ANTLR CLI on combined/split grammars,
listener/visitor flags, and exact emitted ATN equality with `.interp` artifacts.
CI regenerates and compiles the native-target fixtures as well.

The handwritten runtime tests additionally cover all truncated prefixes of a
real parser ATN, corrupted headers and section data, trailing serialized data,
unknown rules, explicit work limits, Unicode positions and invalid JSON.
They also cover every truncated prefix of the lexer artifact and two sentinel
mutations at every field of the JSON lexer/parser and mode lexer artifacts.
Structural validation checks block/loop references, decision tables, rule stop
states, symbol bounds and mode/action indices before execution.

`python tools/check_cli.py` exercises the command as an external JSON consumer.
The arithmetic evaluator and CSV reader have application-level tests alongside
the Java conformance corpus.

Regenerate with Java 17, Python 3.10+ and the official complete JAR:

```sh
python tools/oracle.py --jar /path/to/antlr-4.13.2-complete.jar
moon fmt
moon test --deny-warn
```

Use `--java` and `--javac` for explicit executable paths. The JAR SHA-256 is
verified before use. Temporary files live under the ignored `.local/` directory;
generated source comments contain grammar basenames and hashes, not local paths.

CI checks, builds, tests and runs the example on wasm, wasm-gc, JS and Linux
native. A separate job regenerates the grammar artifacts and Java-reference
tests, then rejects any difference from the committed outputs.

## Official functional descriptors

The 350 static functional descriptors in all 13 ANTLR 4.13.2 categories are
preserved and executed against both targets. See
[corpus provenance and exact assertions](../conformance/README.md).
`tools/upstream_oracle.py` also compares every declared attribute in every rule
frame and observable Parser member state; action offsets come from an
instrumented Java reference. The migration reports every generation failure.
Original stdout is compared for all 350 descriptors, including Parser/Lexer DFA,
listener getters, rule text, Token formatting and predicate observations. Unknown
host actions fail generation. Internal Java runtime API tests are outside this
functional corpus. The 13 lifecycle/label cases additionally check init/after/finally and
synthetic repeated-label capture order. C# snapshots cover all 8 Lexer and 22
preprocessor mutating helper entrances, including their stacks and return values.

The original SLL/LL and tree-building flags configure both reference and native
targets. `tools/lifecycle_oracle.py` adds 34 real Java exception comparisons:
init/after failures, nested finally, recognition and host catch clauses, handler
failures and exception replacement. Application tests also cover disabled-tree
labels and contextual Lexer predicate forwarding through source parsing APIs.
See the [delivery checklist](DELIVERY_CHECKLIST.md) for feature-to-evidence mapping.

`LL_EXACT_AMBIG_DETECTION` and original prediction diagnostic flags are applied
at their original sites. All 17 prediction-report descriptors compare structured
callbacks and exact diagnostic text as well as the full tree. DFA serialization
comes from actual closure sets and visited edges. Lexer predicate-dependent edges
are not cached, and actions in referenced Lexer rules are not committed.
`tools/control_oracle.py` adds 14 independent Java cases for Bail cancellation,
mid-rule tree-building changes and start/stop boundaries of empty rules.
